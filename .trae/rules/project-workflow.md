# 工银牧融项目专属工作流

⚠️ **重要边界**：本规则**仅针对** `C:\Users\WH\Desktop\gonghangbei - 副本` 项目目录内的修改。
- git 操作**只在** `C:\Users\WH\Desktop\gonghangbei - 副本` 目录内执行
- **不要**碰 Desktop 下其他项目或文件
- **不要** `cd` 到其他目录执行 git
- **不要**提交其他项目的变更

## 触发规则：今日工作总结

当用户说类似下面这些话时，**自动执行**两件事，无需再次确认：

触发短语（包括但不限于）：
- "开始今天做的事的总结"
- "今天做的事的总结"
- "总结今天做的事"
- "今天工作总结"
- "今日总结"
- "把今天做的总结一下"

### 第 1 步：更新项目介绍文档

文件：`C:\Users\WH\Desktop\gonghangbei - 副本\项目介绍（ai读）.txt`

更新方式：
1. 更新文件开头的 `最后更新：` 日期为今天
2. 在文件末尾的「附录」章节追加一个新小节「YYYY-MM-DD 工作日志」，包含：
   - 今日新增/修改的文件清单
   - 今日数据变更（哪些 JSON 文件、行数变化）
   - 今日新功能/修复点
   - 遗留问题（如果有）
3. 如果今天有重大架构变更，同步更新文件主体相关章节

### 第 2 步：提交 git（仅项目目录内）

执行命令（按顺序）：
```powershell
# 1. 查看变更
git status

# 2. 添加所有变更（项目目录内）
cd "C:\Users\WH\Desktop\gonghangbei - 副本"
git add -A

# 3. 提交，message 用今日日期 + 简要说明
git commit -m "YYYY-MM-DD: 今日工作总结 - <一句话概述>"

# 4. 推送到远端（如果配置了 remote）
git push
```

注意事项：
- **不要** `git push --force`
- **不要**跳过 hooks（不用 `--no-verify`）
- 如果 commit 失败（pre-commit hook 报错），先修复问题再重新 commit
- 如果没有配置 remote 或 push 失败，告知用户但不要重试 force push
- 提交信息格式参照仓库历史（用 `git log --oneline -5` 查看）

## 识别规则

| 用户输入 | 是否触发 |
|---------|---------|
| "开始今天做的事的总结" | ✅ 触发 |
| "今天工作总结" | ✅ 触发 |
| "总结今天做的事" | ✅ 触发 |
| "今日总结" | ✅ 触发 |
| "把今天做的总结一下" | ✅ 触发 |
| "今天做了什么" | ❌ 不触发（这是询问，不是总结请求） |
| "总结一下这个功能" | ❌ 不触发（这是功能总结，不是今日工作总结） |

## 边界情况

- 如果今天没有任何代码变更（git status 显示 clean），仍更新项目介绍文档的"最后更新"日期，并写一个简短日志说明今天做了什么（即使是"无代码变更"），然后跳过 git commit
- 如果项目介绍文档已经包含今天的日志，不要重复追加，只更新内容
- 如果用户在同一天多次请求总结，只在第一次执行 git commit，后续仅更新文档内容
